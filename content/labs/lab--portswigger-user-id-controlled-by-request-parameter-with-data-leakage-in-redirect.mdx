# Lab: User ID controlled by request parameter with data leakage in redirect

## Objective
This lab contains an access control vulnerability where sensitive user information is leaked within the body of a 302 redirect response. To solve the lab, obtain the API key for the user `carlos` and submit it as the solution.

You can log in to your own account using the following credentials: `wiener:peter`

## Why This Works (The Principle)
- **The vulnerability:** The application redirects the user but still includes sensitive data in the redirect response body.
- **Root cause:** The server returns data in the response body before issuing a redirect, assuming the client won't read it.
- **Exploitation:** Intercept the redirect response in BurpSuite to read the leaked data before the browser follows the redirect.
- **Key insight:** HTTP redirects (301/302) can still contain a response body — don't assume the browser is the only reader.
