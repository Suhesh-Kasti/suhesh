# Portswigger SQL Injection Lab 2

The login form drops your input straight into the query, so the username field can close the string and comment out the password check.

## The vulnerable query

```sql
SELECT * FROM users WHERE username = 'administrator' AND password = 'password'
```

## The payload

Username:

```text
administrator'--
```

Password: anything you like, even blank.

The query becomes:

```sql
SELECT * FROM users WHERE username = 'administrator'--' AND password = ''
```

The `--` comments out the password check, so the WHERE clause is just `username = 'administrator'` and the login succeeds.

## Why it works

The `'` closes the username string and `--` turns the rest of the line into a comment. The database never evaluates the password condition, so it only has to match a row named `administrator`.

## The fix

Parameterise the query so the username and password are bound as values, not concatenated into the SQL string.
