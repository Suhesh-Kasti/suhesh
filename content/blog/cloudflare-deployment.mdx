# Deploying a Static Site to Cloudflare Pages

A static site is HTML, CSS and JavaScript that is already built. Nothing runs on a server to produce the page, so there is almost nothing to host. That is the whole reason Cloudflare Pages will host one for free. I use it for this site.

## What a Static Site Is

A static site is pre-rendered and served as-is. No server-side language (PHP, Ruby, Python) runs when someone opens a page. The entire site already exists as HTML, CSS and JS files, and the host just hands those files to the browser.

That makes static sites faster and safer than dynamic ones. There is no server code to attack and no database to knock over. They are also easy to update: push to Git, the host rebuilds, done. Blogs, portfolios, docs and small web apps all fit this shape.

## What the Free Plan Includes

The free plan is genuinely enough for a small site. The limits that matter:

| What | Free plan |
|------|-----------|
| Continuous deployment | Auto-deploys every time you push to Git |
| Global CDN | Files served from Cloudflare's edge network |
| SSL/HTTPS | Free |
| Bandwidth | 100 GB per month |
| Build minutes | 500 per month |
| Custom domains | Only `*.pages.dev` subdomains; your own domain needs a paid plan |

If you outgrow the bandwidth or need your own domain, that is when you look at a paid plan. For a portfolio or a blog, you won't.

## Deploying Your Site

> For this demo I used [bridget](https://github.com/Sped0n/bridget), a gallery app built with SolidJS and Hugo.

1. **Put your site in a public repo.** Cloudflare Pages on the free plan only reads public GitHub or GitLab repos. If you need a hand pushing code, I wrote about it in [Git Basics: Part 1](/braindump/github-basics-1).

2. **Open the Cloudflare dashboard.** Log in and find the project area.

   ![Cloudflare dashboard after logging in, with the account navigation on the left](/images/content/deployment/cloudflare/dashboard.webp)

3. **Create a project.** This starts a new static site project.

   ![Cloudflare dashboard with the Create a project button](/images/content/deployment/cloudflare/create-project.webp)

4. **Go to Workers & Pages**, then pick Pages.

   ![Workers & Pages section open in the Cloudflare dashboard](/images/content/deployment/cloudflare/pages.webp)

   Click **Connect to Git** and choose where your repo lives, GitHub or GitLab.

5. **Choose the repository** you want to deploy.

   ![Repository picker listing the Git repos connected to Cloudflare](/images/content/deployment/cloudflare/choose-repo.webp)

6. **Configure the build.** Cloudflare tries to detect your framework automatically. Change the preset if it guessed wrong.

   ![Project build settings showing the framework preset and build command fields](/images/content/deployment/cloudflare/configure-project.webp)

   Then click **Deploy**. Cloudflare pulls the code, builds it, and publishes the output.

7. **Done.** With no build errors, the site is live at `YOUR_PROJECT_NAME.pages.dev` within a minute.

   ![Deployment success screen showing the live pages.dev URL](/images/content/deployment/cloudflare/deployed.webp)

From here, every push to the repo triggers a rebuild and redeploy automatically.

## When a Deploy Fails

Deploys fail for a handful of boring reasons. The log is where you find out which one.

![Failed deployment build log inside the Cloudflare dashboard](/images/content/deployment/cloudflare/error.webp)

<Accordion title="Where the log lives" color="#ff5500">

Click the **Deployments** tab and open the failed build. It shows which step died, usually the build itself.

</Accordion>

<Accordion title="Build failed on your code" color="#ff5500">

Fix the errors locally, push, then hit **Retry deployment** in the dashboard.

</Accordion>

<Accordion title="A single file is too large" color="#ff5500">

Cloudflare Pages caps individual file size. Big images and videos are usually the culprit. Compress them, or serve those files from somewhere else.

</Accordion>

<Accordion title="Unknown error" color="#ff5500">

Sometimes a retry just works. If it doesn't, the deploy log is the only place worth looking before you bother Cloudflare support.

</Accordion>

Once the build passes, the deployment flips to available:

![Deployment finished and available at the pages.dev subdomain](/images/content/deployment/cloudflare/available.webp)

## Supported Frameworks

Cloudflare Pages is not tied to one framework. These are the common ones:

| Framework | Notes |
|-----------|-------|
| Hugo | Go-based static generator, very fast builds |
| Jekyll | Ruby, the GitHub Pages default |
| Eleventy (11ty) | Minimal JS static generator |
| Astro | Content-first, ships almost no JavaScript |
| SvelteKit | Static output with the static adapter |
| Next.js | Exported static, or run as a full app |
| Nuxt | Vue's static and hybrid framework |
| Gatsby | React static generator |
| Create React App | Builds to a `build/` folder |
