# Lab: File path traversal, traversal sequences blocked with absolute path bypass

I spent the first few minutes trying nested sequences, because that is the reflex after the non-recursive lab. It was wasted effort. This app blocks traversal properly, and the way in is the opposite of traversal: an absolute path.

## The setup

Same image loader, `GET /image?filename=<name>`. A real image filename works. Anything containing `../` is rejected outright, a straight block with no stripping. So the relative route is closed.

The thing worth noticing is that the endpoint takes a filename and nothing else. There is no visible base directory in the request, which means the base is added server-side. That server-side join is where this breaks.

## How the vulnerability works

Blocking `../` defends against relative escapes. It does nothing about absolute ones. The server builds the path as a join of the image directory and the filename, and in most languages a second argument that starts with a slash replaces the base completely. The developer guarded one direction of escape and forgot the other.

## Solving it

1. Capture a normal image request and confirm `../` is blocked, so you know the filter is active rather than returning an error for some other reason.
2. Put an absolute path straight into the parameter:

```
filename=/etc/passwd
```

3. Send it. The response body is the passwd file. No traversal, no encoding, nothing clever.

## Why that payload works

The path starts with a slash, so the operating system treats it as absolute and never consults the directory the app intended to confine you to. In Python, `os.path.join('/var/www/images', '/etc/passwd')` returns `/etc/passwd`: the base argument is discarded the moment the second argument is absolute. Even a naive string join, `'/var/www/images/' + '/etc/passwd'`, produces `//etc/passwd`, and the kernel collapses the double slash to `/etc/passwd`. Either way the base directory is gone, and the blacklist that only knows about `../` never fires.

## The fix

Validate the resolved path, not the input text. Reject absolute paths, canonicalise the join, and require the result to live under the media directory:

```python
base = "/var/www/images"
resolved = os.path.realpath(os.path.join(base, filename))
if not resolved.startswith(base + os.sep):
    raise Forbidden()
```

A blacklist of traversal strings will always miss a case. A positive check that the final path is inside the allowed directory covers relative traversal and absolute paths in one test.
