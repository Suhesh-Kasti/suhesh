## Welcome to the [DNS](/braindump?tag=DNS) Primer

Type `suhesh.com.np` into a browser and hit Enter. You never typed an IP address, and you never needed to. DNS turned the name you know into the address the network needs.

The usual analogy holds up: DNS is the contacts app of the internet. You remember "mom", the phone remembers the number. You remember the name, DNS resolves the rest.

![The local hosts file open in a text editor with a name pointed at an IP address by hand](/images/content/dns101/hosts_file.webp)

## What the Series Was Meant to Cover

This was going to be part one of a DNS series, hands-on rather than reading slides. Parts two through four never got written, so this is all there is:

- How a lookup actually happens, step by step
- The record types that matter, and when each one is used
- Security, including DNSSEC and why DNS is a favourite attack surface
- The tools, `dig` and `nslookup`, used properly
- Scaling DNS, with hands-on work on an F5 DNS setup

## What You Need to Follow Along

A terminal and a bit of curiosity. If you can run `dig`, you can keep up.

If you run your own resolver, the first thing you check is whether the service is up.
