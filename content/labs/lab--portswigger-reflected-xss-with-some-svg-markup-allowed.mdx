# Lab: Reflected XSS with some SVG markup allowed

The WAF blocks the usual suspects but has clearly never read the SVG spec. I tried a bare `<svg>` on its own and got nowhere, then used Intruder to find which SVG element and which event were still breathing.

## The setup

The search box reflects your input with no escaping, and a block-list sits in front of it. Common HTML tags such as `img`, `script`, and `body` are rejected, and so are common events. The lab summary says some SVG markup is allowed, so the real task is finding which piece, because throwing `<svg>` alone does nothing on its own.

## How the vulnerability works

SVG has its own element and event sets, separate from the HTML ones. `animatetransform` is an SVG element, and `onbegin` is an SVG animation event that fires when the animation starts. A block-list tuned for HTML tags and HTML events tends to miss both, because nobody writing the list thought about SMIL animation. The event fires on its own as soon as the animation begins, which also satisfies the no-interaction rule.

## Solving it

1. Confirm `<svg>` reflects. Send a search term of `<svg>` and check the response.
2. Fuzz elements. Put the payload position inside the tags and run a list of SVG element names.
   ```
   <svg><§tag§>
   ```
   `animatetransform` comes back unblocked.
3. Fuzz events on that element.
   ```
   <svg><animatetransform §onbegin§=alert(1)>
   ```
   `onbegin` passes the filter.
4. Put it together as the final search term.
   ```
   <svg><animatetransform onbegin=alert(1) attributeName=transform>
   ```
5. Load the URL with the term URL-encoded, and the alert fires as the animation starts.

## Why that payload works

`onbegin` runs when the SMIL animation starts, so it needs no user input. `animatetransform` is a valid animation target, and naming `attributeName=transform` gives it an attribute to animate, so the animation genuinely begins instead of sitting idle. The block-list simply never included those SVG-only names.

## The fix

HTML-encode the reflected input so the angle brackets cannot open an element. A deny-list spanning both HTML and SVG is an endless chore with an obvious ceiling; correct output encoding removes the whole class of bug without needing to know every tag name.
