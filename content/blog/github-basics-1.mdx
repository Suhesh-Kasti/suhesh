# Demystifying Git and GitHub for Beginners

Git and GitHub get used like they are the same word. They are not. Git is the version control system that runs on your machine. GitHub is a website that hosts Git repositories so you can back them up and share them. You can use Git without GitHub. You can't use GitHub without Git.

![An illustration contrasting Git, which runs locally, with GitHub, which hosts the repository online](/images/content/github-basics-1/git01.webp)

## Git vs GitHub

| Comparison Point | Git | GitHub |
|------------------|-----|--------|
| What it is | Version control system | Hosting platform for Git repos |
| Where it runs | Locally, on your machine | In the cloud |
| Needs the internet? | No | Yes, to push and pull |
| Core job | Track changes to files | Store and share repositories |
| Account needed? | No | Yes |
| Alternatives | Mercurial, SVN | GitLab, Bitbucket |

Once that clicks, the rest of Git is just remembering the commands.

## The Commands You Actually Use

Three commands do most of the work. Everything else is a variation on them.

```bash
git init                              # start tracking a folder
git add .                             # stage every change
git commit -m "add the login page"    # snapshot what is staged
git remote add origin https://github.com/you/repo.git
git push -u origin main               # send those commits to GitHub
```

`git add` picks what goes into the next snapshot. `git commit` takes that snapshot. `git push` sends your snapshots to GitHub. People mix up add and commit all the time, then wonder why the file they edited is still the old version.

<IdeaNode color="green">The three states to keep in your head: **working tree** (files as you edit them), **staging area** (what `git add` selected), **repository** (the committed history). Every Git command moves changes between those three.</IdeaNode>

## The Daily Loop

After the first push, you repeat one small loop forever:

1. Edit files.
2. `git add` the changes you want.
3. `git commit -m "..."`.
4. `git push`.

That is it. Branches, merges and rebases come later, and you can go far with just this loop.
