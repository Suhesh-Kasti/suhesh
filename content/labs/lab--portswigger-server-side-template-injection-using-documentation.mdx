The content editor lets you edit product descriptions, and they contain syntax I did not recognise: `${something}`. Rather than guess the engine, I broke it on purpose and let the error introduce itself. Ten seconds later I had a name and a documentation page.

## The setup

Log in as `content-manager:C0nt3ntM4n4g3r`. On a product page the description is a template; it is full of placeholder expressions like `${productName}` that get filled in when the page renders. You can edit that source and save it. So you are writing code the server will run.

## How the vulnerability works

Because you control template source, you control what the server executes. To identify the engine, submit a reference to a variable that does not exist, `${foobar}`. The error that comes back names FreeMarker and shows a Java stack trace. FreeMarker's documentation is honest about a sharp edge: the `new()` built-in can instantiate arbitrary Java classes that implement the `TemplateModel` interface. One of those classes, `freemarker.template.utility.Execute`, runs shell commands. That is a documented footgun, not a clever guess.

## Solving it

1. Log in with the content-manager credentials and open a product's description template.
2. Replace a placeholder with `${foobar}` and save. Read the error: FreeMarker on the JVM.
3. In the FreeMarker docs, find the FAQ about user-supplied templates and the `new()` entry, then follow it to the `TemplateModel` JavaDoc and the `Execute` class.
4. Write the exploit. This is @albinowax's known payload:

```
<#assign ex="freemarker.template.utility.Execute"?new()> ${ ex("rm /home/carlos/morale.txt") }
```

5. Remove the `${foobar}` you left earlier, save the template with this in its place, and view the product page. The command runs.

## Why that payload works

`?new()` builds an object from the class name it is given, so the string `freemarker.template.utility.Execute` becomes a live `Execute` instance bound to `ex`. Calling `ex("...")` invokes its command execution with the string you pass. `${ ... }` then interpolates the result into the page, which is why the expression is evaluated at all. You are not running `Runtime.exec` directly, because FreeMarker will not let you name that class; you are using the one class it will build for you.

## The fix

Never render user-editable content as a template. If authors need placeholders, restrict them to a small set of known variables and a safe subset of the language. Configure FreeMarker without the object-creation built-ins, and treat a template editor as a privileged, non-public feature.
