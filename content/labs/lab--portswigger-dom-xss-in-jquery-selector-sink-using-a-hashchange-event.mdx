# Lab: DOM XSS in jQuery selector sink using a hashchange event

## Objective
This lab contains a DOM-based cross-site scripting vulnerability on the home page. It uses jQuery's `$()` selector function to auto-scroll to a given post, whose title is passed via the `location.hash` property.
To solve the lab, deliver an exploit to the victim that calls the `print()` function in their browser.

## Why This Works (The Principle)
- **The vulnerability:** Client-side JavaScript writes attacker-controlled data to the DOM without sanitization.
- **Root cause:** The application uses a dangerous sink (e.g., `document.write`, `innerHTML`, jQuery selector) with user-controllable source (e.g., `location.search`, `location.hash`).
- **Exploitation:** Craft a URL with a malicious payload in the fragment or query string. When the victim visits it, client-side code executes the payload.
- **Key insight:** DOM-based XSS does not require the server to reflect the payload — it lives entirely in the client-side code path.

## Key Takeaway
##### Dismantling the Payload
`<iframe src=[https://target.net/#](https://target.net/#) onload="this.src+='<img src=x onerror=print()>'"></iframe>`
### 1. `src="[https://target.net/#](https://target.net/#)"` (The Initial Load)

- **Why it's there:** You open an `<iframe>` loading the target site with a blank hash (`#`).
- **What happens:** The target site loads completely in the victim's browser. The application sets up its JavaScript listener: `$(window).on('hashchange', ...)`.
### 2. `onload="..."` (The Automation Trigger)
- **Why it's there:** You need the victim's browser to perform an action _after_ the page finishes loading.
- **What happens:** The instant the target page finishes loading inside the `<iframe>`, the browser automatically executes the JavaScript inside `onload`.
### 3. `this.src += ...` (The `hashchange` Exploit)
- **Why it's there:** `this` refers to the `<iframe>`. Updating `this.src` changes the iframe's URL.
- **What happens:** The URL changes from `[https://target.net/#](https://target.net/#)` to `[https://target.net/#](https://target.net/#)<img src=x onerror=print()>`.
- Because the URL changed _after_ the page loaded, the browser fires the **`hashchange`** event!
### 4. `'<img src=x onerror=print()>'` (The jQuery Payload)
- **Why it's there:** The target's `hashchange` script takes `location.hash` and passes it directly to `$(location.hash)`.
- **What happens:** Older versions of jQuery see `<img...>` and think, _"Oh, the developer wants me to create a new image element!"_ It creates the `<img>` tag, tries to load image `x`, fails, and immediately executes `onerror=print()`.
