The `message` parameter is meant to hold one boring sentence, and it does render as text when you send text. Then you send a little arithmetic and the page answers with a number. That is the whole tell: your input is not being displayed, it is being executed.

## The setup

The home page has a "view details" link that fires a `GET` request such as `/?message=Unfortunately this product is out of stock`, and the value is echoed onto the page. Send `?message=hi` and you get `hi` back. The reflection is on the page, and the app is written in Ruby.

## How the vulnerability works

The app builds an ERB template string with your `message` value concatenated into it, then renders that template. ERB is Ruby's template engine, and anything inside `<%= ... %>` is evaluated as Ruby and printed. Because your text has become template source rather than data, the engine runs it. The developer meant for you to pass a string; you are editing the program.

## Solving it

1. Confirm the reflection with `GET /?message=hi`.
2. Prove it is evaluated, not escaped. Send this as the message value:

```
<%= 7*7 %>
```

URL-encoded, that is `/?message=<%25%3d+7*7+%25>`. The page shows `49` where your message should be.
3. Ruby's `system()` runs an operating system command. Delete Carlos's file:

```ruby
<%= system("rm /home/carlos/morale.txt") %>
```

4. URL-encode it and send `GET /?message=<%25+system("rm+/home/carlos/morale.txt")+%25>`. The file is removed and the lab goes green.

## Why that payload works

ERB compiles the template into Ruby, so `<%= expression %>` executes the expression and writes its return value into the output. `7*7` returns `49`, which is why you saw the number. `system()` hands its string to the shell, so the `rm` runs with the web server's privileges. Nothing depends on finding a hidden object or a gadget; the template itself is the sink, and you supply the code.

## The fix

Never concatenate user input into template source. Pass the message as a variable that the engine substitutes at render time, so the string is treated as data and printed, not parsed. Keep a strict line between templates, which are trusted, and the values they render, which are not, and escape output for the context it lands in.
