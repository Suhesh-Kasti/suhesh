# Lab: Stored XSS into HTML context with nothing encoded

## Objective
This lab contains a stored cross-site scripting vulnerability in the comment functionality. To solve this lab, submit a comment that calls the `alert` function when the blog post is viewed.

## Why This Works (The Principle)
- **The vulnerability:** User-supplied input is stored and then embedded into a web page without any escaping, allowing arbitrary JavaScript execution for every visitor.
- **Root cause:** The application stores attacker-controlled data and outputs it into an HTML context without sanitization or encoding.
- **Exploitation:** Submit a simple `<script>alert(1)</script>` payload in a comment field that executes when any user views the page.
- **Key insight:** Stored XSS is more dangerous than reflected XSS because it affects every user who views the page, not just the user who clicks a crafted link.

## Solution Reconstruction
- [ ] Step 1: Navigated to a blog post with a comment section
- [ ] Step 2: Injected `<script>alert(1)</script>` into the comment body
- [ ] Step 3: Submitted the comment and verified the alert fired when viewing the blog post
- [ ] Final payload / exploit: `<script>alert(1)</script>`
