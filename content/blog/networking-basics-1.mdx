Two models describe the same thing: how data gets from one machine to another. OSI is the seven-layer teaching model. TCP/IP is the four-layer model the internet actually runs on. Learn both and you stop guessing where a problem lives.

![Computers and network devices connected on a network, moving data between machines](/images/content/networking/networking01.webp)

## The OSI Model

Seven layers, bottom to top:

| # | Layer | What it does | Example |
|---|-------|--------------|---------|
| 7 | Application | What the user talks to | HTTP, DNS, SSH |
| 6 | Presentation | Encoding and encryption | TLS, JPEG |
| 5 | Session | Opens and keeps a conversation | Session tokens, RPC |
| 4 | Transport | End-to-end delivery, ports | TCP, UDP |
| 3 | Network | Routing between networks | IP, ICMP |
| 2 | Data link | Delivery on the local link | Ethernet, MAC |
| 1 | Physical | The wire and the bits | Cables, radio |

## The TCP/IP Model

Four layers, which is what the real stack uses:

| Layer | Maps to OSI | Example |
|-------|-------------|---------|
| Application | 5 to 7 | HTTP, DNS, TLS |
| Transport | 4 | TCP, UDP |
| Internet | 3 | IP |
| Network access | 1 and 2 | Ethernet, Wi-Fi |

## How They Line Up

OSI's top three layers collapse into TCP/IP's Application layer. Its bottom two collapse into Network access. The middle two, Transport and Internet, stay as they are. That is the whole mapping.

## Encapsulation

When you send a request, each layer wraps the one below it. Your HTTP request becomes a TCP segment, then an IP packet, then an Ethernet frame. On the other end the wrapping comes off in reverse order.

This is why people say "layer 2 problem" or "layer 3 problem". They mean: how far down the stack is this broken? A wrong cable is layer 1. A wrong route is layer 3. A refused connection is layer 4.
