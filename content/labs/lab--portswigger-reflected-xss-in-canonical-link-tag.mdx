## Why This Works (The Principle)
- **The vulnerability:** User-supplied input is embedded into a web page without proper escaping, allowing arbitrary JavaScript execution.
- **Root cause:** The application outputs attacker-controlled data into an HTML context, attribute, or JavaScript context without sanitization.
- **Exploitation:** Inject a payload that escapes the current context (e.g., `>` to break out of an HTML tag, `"` to break out of an attribute).
- **Key insight:** XSS is context-dependent — the same payload will not work in every injection point. Always identify the context first.

## Key Takeaway
#### What's a rel="canonical" that says "Hey, the official URL for this page is the exact page you are looking at right now"
Imagine you run an online clothing store, and you have a page for a blue shirt. To a human, it's just one page. But users (and tracking bots) can arrive at that page using many slightly different URLs:
- `https://example.com/blue-shirt` (The clean, main link)
- `https://www.example.com/blue-shirt` (With `www`)
- `http://example.com/blue-shirt` (Unsecured `http`)    
- `https://example.com/blue-shirt?size=small` (With a filtering parameter)
- `https://example.com/blue-shirt?utm_source=twitter` (With a social media tracking code)
To Google's search bot, **every single one of those URLs is treated as a completely separate webpage.** Without a canonical tag, Google looks at those 5 URLs, sees the exact same blue shirt on all of them, and thinks, _"This website is spamming the internet with 5 copies of the exact same page!"_ As a result, Google might penalize your site's ranking, or split your search engine juice (SEO value) across all 5 separate links instead of concentrating it on one.
To fix this, developers put a canonical tag on the page that points to the **clean, master version** of the URL.
- If a user (or Google) lands on the messy tracking URL: `https://example.com/blue-shirt?utm_source=twitter`
- The code hidden in the background says: `<link rel="canonical" href="https://example.com/blue-shirt" />`
This tells Google: _"Hey, I know you found me through a messy Twitter tracking link, but please don't index this messy URL. The official, master version is just `https://example.com/blue-shirt`. Put all our SEO credit there."_
Even when viewing the clean page (`https://example.com/blue-shirt`), developers still include that tag pointing to itself as a **preventative shield**.
They don't always know _how_ a user or a rogue bot might alter the URL in the future (by adding tracking codes, session IDs, or search parameters). By having the page permanently shout, _"No matter what extra text gets added to the end of this URL, this exact clean address is the master copy,"_ they protect the website's Google ranking from getting messed up.

#### Accesskey HTML attribute
The `accesskey` attribute in HTML is a global attribute that allows you to assign a custom keyboard shortcut to an element on a webpage. When a user presses a specific combination of keys (which varies depending on their operating system and browser) along with the assigned `accesskey`, the browser brings focus to or activates that element.

Historically, the `accesskey` attribute was introduced with two main goals in mind:
- **Accessibility:** To help users who rely on keyboard navigation or assistive technologies (like screen readers) navigate a website more efficiently without needing a mouse.
- **Efficiency:** To allow "power users" to quickly trigger frequent actions, such as jumping to a search bar, clicking a "Submit" button, or returning to the home page.

You simply add the attribute to an HTML tag and assign it a single character.
``` html
<a href="/home" accesskey="h">Home</a>

<input type="text" placeholder="Search..." accesskey="s">

<button type="submit" accesskey="c">Submit Form</button>
```
To trigger these shortcuts, the user has to press a combination of modifier keys alongside the character you assigned. This is where it gets a bit complicated, because the modifiers change depending on the user's setup:
- **Windows / Chrome & Edge:** `Alt` + `key`    
- **Windows / Firefox:** `Alt` + `Shift` + `key`
- **Mac / Chrome, Safari, & Firefox:** `Control` + `Option` + `key`

> **Note:** Sometimes if a certain character is URL encoded we can bypass [url encoding](https://www.w3schools.com/tags/ref_urlencode.ASP) using TABs and LINE FEEDs.
