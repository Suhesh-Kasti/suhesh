# Lab: Information disclosure in version control history

I already knew the `.git` trick, so the only real work here was getting the dump onto disk. The dumper bit me with a missing Python module, and the fix is a one-liner I now keep in my notes. The rest is just reading git output.

## The setup

Browsing to `/.git/` returns a directory listing of the repository internals. Nothing hides it, and no authentication is involved. The whole history is being served like any other folder of files.

## How the vulnerability works

Git keeps everything in `.git`: objects for every file at every commit, refs, and logs. If the web server serves that directory, you can rebuild the source and walk the history. Secrets that were removed in a later commit are still sitting in the objects of the earlier one, so `git show` or `git diff` on the old commit prints exactly what was deleted.

## Solving it

1. Confirm the leak: `GET /.git/` answers with a listing.
2. Download the repository. A dedicated dumper is cleaner than `wget -r`:

```bash
git-dumper https://LAB-ID.web-security-academy.net/.git/ ./repo
```

My first run died with `ModuleNotFoundError: No module named 'requests_pkcs12'`. Running the tool in a throwaway environment that carries the extra dependency fixed it:

```bash
uvx --with requests_pkcs12 git-dumper https://LAB-ID.web-security-academy.net/.git/ ./repo
```

`uvx` is short for `uv tool run`: it builds a temporary environment with `git-dumper` and `requests_pkcs12`, then executes the tool there.

3. Walk the history in `./repo`:

```bash
git log --oneline
git show HEAD~1 -- admin.conf
```

A commit titled "Remove admin password from config" is the tell. Its diff swapped the hard-coded password for `env('ADMIN_PASSWORD')`, and the old password is still visible on the removed line.

4. Log in as `administrator` with the leaked password, open the admin panel, and delete `carlos`.

## Why that payload works

Nothing clever. `.git` is a static directory and the server hands out its files like any other. The dumper replays the usual repository responses; once the objects are local, `git show` reconstructs the previous file byte for byte, secrets included.

## The fix

Never deploy `.git` into the document root. Build the artifact without VCS metadata and block dotfiles and dot-directories at the web server or CDN. If a secret ever touched a commit, rotate it, because deleting it later does not remove it from the object store.
