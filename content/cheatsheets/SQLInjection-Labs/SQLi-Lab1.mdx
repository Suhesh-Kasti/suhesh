The product category filter is the injection point. The app builds the query by hand, so a quote in `category` breaks out of the string.

## The vulnerable query

```sql
SELECT * FROM products WHERE category = 'Gifts' AND released = 1
```

Two things matter: the value sits inside single quotes, and the trailing `AND released = 1` is what hides unreleased products.

## The payload

Set the `category` parameter to:

```text
Gifts' OR 1=1--
```

The query becomes:

```sql
SELECT * FROM products WHERE category = 'Gifts' OR 1=1--' AND released = 1
```

The `--` comments out everything after it, so `released = 1` no longer applies and every product returns. In the browser the payload is URL-encoded:

```text
/filter?category=Gifts'+OR+1=1--
```

## Why it works

`OR 1=1` is always true, so the WHERE clause matches every row. The `--` comment eats the closing quote and the `AND released = 1` filter that would otherwise hide the unreleased items.

## The fix

Use a parameterised query so the category is passed as data, never concatenated into the SQL string.
