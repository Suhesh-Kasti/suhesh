Here the injection point is not a message that gets rendered. It is a setting, your comment display name, that the app splices into Tornado template code. My first payload did the maths and left a stray `}}` on the page, and that leftover brace is the best confirmation I have found that I am inside the template.

## The setup

Log in as `wiener:peter` and post a comment. On the account page you choose how your name is shown: full name, first name, or nickname. Submitting sends `POST /my-account/change-blog-post-author-display` with a parameter set to `user.name`, `user.first_name`, or `user.nickname`. Reload the post and the name above your comment updates from that value.

## How the vulnerability works

The server stores that parameter and drops it into a template expression. The app expects one of the three fixed strings, but you control the whole field. So your value starts its life inside Tornado's `{{ ... }}`, and you only have to close the expression to get out. Anything you add after the closing braces becomes new template code. Tornado expressions are `{{ }}`; statements, including imports, are `{% %}`. That is enough to reach Python.

## Solving it

1. Post a comment and change your display name, confirming it appears above the comment.
2. Break out of the expression and do arithmetic. Set the parameter to:

```
user.name}}{{7*7}}
```

Reload the comment. The name reads something like `Peter Wiener49}}`. The `49` is server-side evaluation; the trailing `}}` is Tornado's leftover from the expression you closed early.
3. Tornado runs Python inside `{% %}`. Import `os` and call `system()`:

```
{% import os %}{{os.system('rm /home/carlos/morale.txt')}}
```

4. In Repeater, set `blog-post-author-display=user.name}}{%25+import+os+%25}{{os.system('rm%20/home/carlos/morale.txt')`, then reload the comment page.

## Why that payload works

Your value already sits inside `{{ }}`, so the first `}}` ends the app's expression early and `{{7*7}}` is evaluated as a fresh one, which is why a literal `49` and a dangling brace show up together. `{% import os %}` is a statement, and `{{os.system(...)}}` calls it. Tornado does not sandbox template code, so once you are inside the template you are in Python, with the server's privileges.

## The fix

Do not let the request name the expression. Map the three allowed choices to fixed values server-side with an allow-list, or pass the chosen display string as a variable that the template prints. The parameter should select from your values; it should never be copied into template source.
