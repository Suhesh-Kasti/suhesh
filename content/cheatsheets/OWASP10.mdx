# OWASP Top 10

The ten risk categories from the 2021 list, A01 to A10. Each one gets a two-line summary and, where it helps, a snippet of the broken code that causes it.

## A01: Broken Access Control

Access control checks are missing or easy to bypass, so a user reaches data that isn't theirs. The usual shape is an ID in the request that nobody validates.

<Accordion title="Insecure code — horizontal privilege escalation">
```php
$user_id = $_GET['user_id'];
$query = "SELECT * FROM users WHERE id = $user_id";
$result = $conn->query($query);
```
The query trusts `user_id` from the URL, so any logged-in user can read any account.
</Accordion>

## A02: Cryptographic Failures

Sensitive data is stored or moved without proper encryption: weak algorithms, wrong modes, missing TLS.

<Accordion title="Insecure code — ECB mode">
```java
Cipher cipher = Cipher.getInstance("AES/ECB/PKCS5Padding");
cipher.init(Cipher.ENCRYPT_MODE, secretKey);
byte[] cipherText = cipher.doFinal(plainText);
```
ECB encrypts identical blocks to identical output, so it leaks the structure of the plaintext.
</Accordion>

## A03: Injection

Untrusted input reaches an interpreter — SQL, NoSQL, OS, LDAP — or reaches the browser as XSS, and gets run as code.

<Accordion title="Insecure code — SQL injection">
```python
user_input = request.args.get('user_input')
query = f"SELECT * FROM users WHERE name = '{user_input}'"
result = db.execute(query)
```
The f-string drops user input straight into the query string.
</Accordion>

## A04: Insecure Design

The flaw is in the design rather than the code. Missing threat modeling, missing rate limits, missing business-logic controls.

## A05: Security Misconfiguration

Default credentials, verbose errors, open cloud storage, missing headers, unpatched defaults. The most common finding by volume.

<Accordion title="Insecure config — XXE enabled">
```xml
<?xml version="1.0"?>
<!DOCTYPE root [
<!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<root>&xxe;</root>
```
The XML parser resolves external entities, so the attacker reads local files through the request body.
</Accordion>

## A06: Vulnerable and Outdated Components

You run a library, framework, or OS build with a known CVE. The app is only as strong as its dependencies.

## A07: Identification and Authentication Failures

Weak login, broken session handling, credential stuffing, session fixation — anything that lets someone else become the user.

<Accordion title="Insecure code — session fixation">
```javascript
function createSession() {
  const sessionId = req.cookies.sessionId || uuid.v4();
  res.cookie("sessionId", sessionId);
  sessions[sessionId] = {};
}
```
The server keeps a client-supplied session id instead of issuing a fresh one after login.
</Accordion>

## A08: Software and Data Integrity Failures

Code or data is trusted without checking integrity: unsigned updates, an insecure CI/CD pipeline, unsafe deserialization.

## A09: Security Logging and Monitoring Failures

Breaches go undetected because nothing useful is logged and nobody watches the logs. Detection often comes from outside the org.

## A10: Server-Side Request Forgery (SSRF)

The app fetches a user-supplied URL and will happily hit internal services sitting behind the firewall.

<Accordion title="Insecure code — SSRF">
```ruby
url = params[:url]
response = Net::HTTP.get_response(URI(url))
```
No allow-list, so `url` can point at `http://169.254.169.254/` or any internal host.
</Accordion>
