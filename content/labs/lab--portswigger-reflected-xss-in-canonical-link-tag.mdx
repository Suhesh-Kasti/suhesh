# Lab: Reflected XSS in canonical link tag

The angle brackets are escaped, so the obvious move is gone and the payload has to live inside a single attribute. What finally worked was less about XSS and more about remembering that URLs treat tab characters as whitespace.

## The setup

The home page has a `<link rel="canonical" href='...'>` tag, and its value is the current request URL reflected back without escaping. Because the reflection sits inside an attribute, escaping `<` and `>` does nothing to stop you from closing the attribute and adding new ones. The lab also tells you the simulated user will press ALT+SHIFT+X and similar combos, which is a very loud hint about which attribute to reach for.

## How the vulnerability works

The canonical link exists to tell search engines the master URL for a page, so the site reflects the current URL into its `href`. That value is user-controlled. The attribute is single-quoted, so a single quote in the path closes it and lets you inject fresh attributes. The key-combo hint points at `accesskey`, a global attribute that binds a keyboard shortcut to an element, and `onclick` to run when it is activated. Neither needs a new tag, which is why the angle-bracket filter is irrelevant here.

## Solving it

1. View the page source and find the canonical link. Confirm your input lands in the `href` unescaped.
2. Break out of the attribute with a single quote, then add `accesskey` and `onclick`.
   ```
   'accesskey='x' onclick='alert(1)
   ```
3. The space between the attributes gets URL-encoded, which kills the injection. Replace each space with a literal tab, sent as `%09`. The final URL looks like:
   ```
   https://YOUR-LAB-ID.web-security-academy.net/?%27accesskey=%27x%27%09onclick=%27alert(1)
   ```
4. Load it and press the access key for your OS. In Chrome that is ALT+SHIFT+X.
5. Deliver the same URL to the victim, who presses the combo.

## Why that payload works

The leading quote closes the `href` value. `accesskey='x'` assigns the shortcut character, and `onclick='alert(1)'` gets closed by the tag's own trailing quote, so the markup stays balanced. The tab is the whole trick: a tab is whitespace to the HTML parser, but the filter only URL-encodes spaces, so `%09` walks past it and still separates the two attributes.

## The fix

Run the reflected URL through `htmlspecialchars` with `ENT_QUOTES` before it touches the attribute, so the single quote becomes an entity and cannot close the value. Building the canonical URL from the validated path only is cleaner still.
